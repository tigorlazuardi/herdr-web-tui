`herdr-web-tui` is one static Go binary (the built frontend is embedded — see
`dist.go`). It requires a running Herdr server reachable via the `herdr` CLI on
`PATH`.

## 1. Install via Nix flake

The repo ships a `flake.nix` (package, dev shell, and a Home Manager module).
It pulls `herdr` straight from `nixpkgs` (`nixos-unstable`), so no separate
herdr flake input is needed.

```bash
nix run   github:tigorlazuardi/herdr-web-tui       # run it
nix build github:tigorlazuardi/herdr-web-tui       # ./result/bin/herdr-web-tui
nix develop                                        # Go + Node dev shell
```

### Home Manager module

```nix
imports = [ herdr-web-tui.homeManagerModules.default ];
services.herdr-web-tui = {
  enable = true;          # systemd *user* service
  server.enable = true;   # also run a managed `herdr server` user service
};
```

herdr package resolution: if your Home Manager provides the `programs.herdr`
module it is auto-enabled and its `programs.herdr.package` is used; otherwise
it falls back to `pkgs.herdr`. Set `herdrPackage` to override either way.

`server.enable` (default `false`) opts into a managed `herdr server` user
service. When on, the web-tui unit is wired `After`/`Requires`/`PartOf` that
server so they start and stop together. When off, no server dependency is
added and you must run the herdr server yourself.

For Web Push, point systemd at a runtime secret file generated by sops-nix,
agenix, or equivalent secret tooling. Do not put `VAPID_PRIVATE_KEY` in
`services.herdr-web-tui.environment`: Nix values can leak into the Nix store or
generated unit.

```nix
services.herdr-web-tui.webPush.environmentFile =
  "/run/user/1000/secrets/herdr-web-push.env";
```

Path must be absolute. `null` (default) omits `EnvironmentFile` and leaves Web
Push disabled unless process environment is supplied another way. Configured
file is required: missing or unreadable file makes systemd fail service startup
rather than silently running without Push configuration.

<Aside>
The module still only speaks plain HTTP with no auth — keep it behind the nginx
gateway (section 3) regardless of how you install it.
</Aside>

## 2. Running the binary (manual)

```bash
go build -o herdr-web-tui ./cmd/herdr-web-tui
./herdr-web-tui
```

Listens on `:8080` by default and serves everything: the embedded frontend, the
`/send` and `/clientlog` APIs, and the `/ws` terminal stream — one process, one
`http.Server` (`cmd/herdr-web-tui/main.go`).

Per browser tab (i.e. per `/ws` connection) the process spawns a Herdr pty via
`herdr --session <name> …` (`internal/pty`); `/send` shells out to
`herdr --session <name> pane current` then `herdr --session <name> pane run …`
(`internal/herdrclient`). Both require the `herdr` binary to be reachable on
`PATH` at runtime.

<Aside type="danger" title="No built-in auth or TLS">
This binary has zero authN/authZ and speaks plain HTTP. It is designed to sit
behind a gateway (nginx) that terminates TLS and handles access control — see
below. Do not expose `:8080` directly to a LAN or the internet.
</Aside>

## 3. Nginx gateway (required)

Nginx sits in front and owns everything security-related — this app has no
opinion on auth or TLS:

- **TLS termination** — nginx.
- **Auth** — nginx (basic auth, an auth subrequest, mTLS, whatever fits) — out
  of this app's scope entirely.
- **Reverse proxy** to `127.0.0.1:8080` (or wherever `--addr` binds).
- **`client_max_body_size`** — the app itself accepts uploads of any size on
  `/send` (no app-side cap); the *gateway* is the place to bound upload size.

### URL routing: `(domain)/(session)`

The frontend derives the Herdr session name from the first path segment of the
URL (`frontend/src/lib/session.ts`, `sessionFromPath`) and sends it as the
`session` query param on `/ws` and the `session` form field on `/send`. So
`https://your-domain/work` renders and injects into the Herdr session named
`work`; `https://your-domain/` (no path segment) falls back to the session
named `default`.

The backend re-validates whatever session name it's given
(`internal/server/session.go`, `sanitizeSession`): only `[a-zA-Z0-9-]` is
allowed, anything empty or non-matching silently becomes `default`. A minimal
proxy passthrough is enough — nginx does not need to parse or rewrite the
session out of the path itself, just forward the request through.

```nginx
server {
    listen 443 ssl;
    server_name your-domain;

    client_max_body_size 200m;  # upload cap; app accepts any size otherwise

    # Concrete secure sample: nginx Basic Auth. Another gateway access-control
    # system is fine if it fails closed before forwarding requests.
    auth_basic "Herdr operator";
    auth_basic_user_file /etc/nginx/herdr-web-tui.htpasswd;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;

        # Required for the /ws upgrade.
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

Run backend on loopback (`--addr 127.0.0.1:8080`) or an equivalent private socket/firewall rule. Never expose backend listener directly: every request reaching it is trusted. Validate gateway access and configured single-server PWA identity before enabling Push. `/manifest.webmanifest` derives bounded `id` and `name` only from `SERVER_NAME`; unauthenticated access remains a gateway concern.

```sh
set -eu
BASE=https://your-domain
OPERATOR=operator
SERVER_NAME=sg-prod-1

[ "$(curl -sS -o /dev/null -w '%{http_code}' --max-filesize 16384 "$BASE/manifest.webmanifest")" = 401 ]
manifest=$(curl -fsS --max-filesize 16384 -u "$OPERATOR" "$BASE/manifest.webmanifest" |
  jq -ce 'select(type == "object") | {id, name} | select(.id | type == "string") | select(.name | type == "string")')
expected_id="/pwa/$(printf %s "$SERVER_NAME" | sha256sum | cut -d' ' -f1)"
[ "$(printf %s "$manifest" | jq -r .id)" = "$expected_id" ]
[ "$(printf %s "$manifest" | jq -r .name)" = "$SERVER_NAME" ]
```

## 4. Background Web Push

Installed Android PWAs can receive agent `done`/`blocked` notifications while closed. HTTPS and gateway access control are required. Service has one global subscription owner; every browser that enables notifications adds an endpoint to that owner's deduplicated list and receives each eligible notification. Registration state remains local to each browser. Focused app windows suppress notification display locally.

Configure VAPID keys outside repository:

```text
VAPID_PUBLIC_KEY=<URL-safe base64 public key>
VAPID_PRIVATE_KEY=<secret URL-safe base64 private key>
VAPID_SUBJECT=mailto:operator@example.com
WEB_PUSH_STORE_PATH=/var/lib/herdr-web-tui/push-subscription.json
HERDR_SOCKET_PATH=/path/to/herdr.sock
```

Environment file must contain all five keys shown above. Use plain systemd
`KEY=value` syntax; do not commit file or generate secrets through Nix. Operator
must create parent directories, provision file at configured runtime path before
service starts, restrict file mode to `0600`, and ensure service user can read
file. Operator must also make `WEB_PUSH_STORE_PATH` parent directory writable by
service user and protect it from other users; subscription store is written
atomically with mode `0600`. Upgrading from the legacy single-subscription format
performs a one-way rewrite on the first subscription mutation. Before rewriting,
the service creates `<WEB_PUSH_STORE_PATH>.legacy-v1.bak` with mode `0600` and
refuses migration if an existing backup differs. Keep this backup until rollback
is no longer required. To roll back: stop the service, copy the backup over
`WEB_PUSH_STORE_PATH`, restore owner/mode `0600`, then start the legacy release;
subscriptions registered only after upgrade must re-enable notifications.
`HERDR_SOCKET_PATH` must name socket service user can access. All three VAPID values must be set together. Key rotation requires
each browser to disable then re-enable notifications. Standard `OTEL_EXPORTER_OTLP_*`
variables enable OTLP traces and metrics; without endpoint providers remain
active for correlated local slog and discard export. Service worker handles
only push/click—no offline cache or fetch interception.

Notification clicks carry only a bounded Herdr `pane_id`. Existing PWA windows receive a service-worker message; cold starts use a same-origin `pane_id` query that is removed after capture. Trusted backend accepts only `application/json`, verifies pane still exists, then sends raw protocol-16 `pane.focus` with `{pane_id}`. Keep gateway CORS same-origin: do not emit `Access-Control-Allow-Origin` for other origins, and reject cross-site `Origin`/`Sec-Fetch-Site` requests when gateway supports those checks. Herdr focus is global/shared across attached clients, so another client can move focus immediately before or after notification handling.

## 5. Environment / flags

Every setting is a flag with an environment-variable fallback of the same
name (`cmd/herdr-web-tui/main.go`, `envOr`); the flag wins if both are set.

| Flag | Env var | Default | Meaning |
|---|---|---|---|
| `--addr` | `ADDR` | `:8080` | Listen address for `http.Server`. |
| `--log-format` | `LOG_FORMAT` | `""` (auto) | `json`, `text`, or empty. Empty auto-detects: `text` on a TTY stdout, `json` otherwise (`internal/logger.New`). |
| `--tmp-prefix` | `TMP_PREFIX` | `herdr-web-tui` | Prefix for the artifact staging directory. |

**Artifact staging path.** `--tmp-prefix` (or `TMP_PREFIX`) becomes
`os.TempDir()/<prefix>-<numeric-effective-uid>` (`internal/artifact.DefaultDir`, equivalent to `id -u`),
created `0700` on startup if missing. `/send` writes every uploaded file here,
flat, as `<xid>[.ext]` (`internal/artifact.SaveFile`) before injecting the
resolved path into the pane.

**Correlation headers.** Not configurable — always `X-Request-Id` and
`X-Correlation-Id` (`internal/correlation.HeaderRequestID` /
`HeaderCorrelationID`), set on every response. An inbound `X-Request-Id` is
echoed back rather than replaced, so a caller/upstream proxy can supply its
own trace id and this service will join it.

## 6. Systemd unit (manual, non-Nix)

On Home Manager, use the flake module (section 1) instead of this unit.

```ini title="/etc/systemd/system/herdr-web-tui.service"
[Unit]
Description=Herdr Web TUI
After=network.target

[Service]
ExecStart=/usr/local/bin/herdr-web-tui --addr :8080
Environment="LOG_FORMAT=json"
Restart=on-failure
User=herdr
# herdr must be resolvable on this user's PATH.

[Install]
WantedBy=multi-user.target
```

## 7. Notes

- **Mobile layout is cols-driven, not a flag.** Herdr's own TUI drops to a
  single-column mobile layout purely from terminal width in columns —
  `[ui] mobile_width_threshold`, default **64 cols** (see the `herdr` skill and
  the `herdr` skill). This app does nothing special for mobile; it just has to
  report the browser's real terminal size accurately: the frontend sends the
  fit-addon's measured size as the very first `/ws` frame before the pty spawns,
  and again on every resize (`internal/server/pty.go`, `readInitialSize` /
  `readLoop` handling `FrameResize`). A phone viewport that ends up ≤ 64 cols
  after that first frame gets Herdr's mobile layout automatically; nothing to
  configure server-side.
- **`/tmp` cleanup is OS-managed.** The app never deletes files from the
  artifact staging dir itself — no TTL, no background sweep. Rely on your
  OS's normal `/tmp` cleanup policy (e.g. `systemd-tmpfiles`, a reboot, or a
  cron job) if you want old uploads reaped.
- **Requires a Herdr server reachable via the `herdr` CLI**, with JSON CLI
  output and the `pane current` / `pane run` subcommands this service shells
  out to (`internal/herdrclient`). Verified live against Herdr 0.7.3.
